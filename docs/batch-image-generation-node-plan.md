# 无限画布批量生图节点计划

## 1. 目标

为无限画布新增“批量生图”节点。用户可以一次上传多张图片，并使用同一个提示词分别处理每张图片。例如上传 10 张模糊照片并输入“高清化处理图片”，节点会创建 10 个独立生图任务，每个任务对应一张上传图片。

节点 UI 参考现有“动作裂变”节点，但不包含动作项目、分类组或动作随机选择逻辑。

## 2. 已确认的核心行为

### 2.1 批量任务模型

- 上传 10 张图片，创建 10 个独立任务。
- 第 `i` 个任务的第一张参考图固定是第 `i` 张导入图片。
- 每个任务只生成 1 张结果。
- 每个任务拥有独立的任务状态、结果、错误信息、重试和下载状态。
- 任意一张图片失败，不影响其他图片继续生成。

示例：

```text
导入图片 A → 任务 1：[A, 连接图 1, 连接图 2]
导入图片 B → 任务 2：[B, 连接图 1, 连接图 2]
导入图片 C → 任务 3：[C, 连接图 1, 连接图 2]
```

### 2.2 混合图片

“混合图片”表示当前导入图片与节点额外连接的图片一起参与生图：

- 当节点存在额外连接图片时，主图片区域显示“混合图片”标签。
- 每个任务的当前导入图片始终位于参考图列表第一位。
- 额外连接图片追加在当前导入图片之后，并应用到每一个任务。
- 没有额外连接图片时，显示普通主图片状态。
- “混合图片”是 UI 和输入语义标识，不额外创建合图任务。

### 2.3 提示词

- 节点提供一个主提示词输入框。
- 节点内提示词应用到所有批量任务。
- 连接到节点的外部提示词也应用到所有任务。
- 继续沿用现有提示词收集和合并规则。
- 没有有效提示词时，节点不可运行并显示配置提示。

### 2.4 图片输入

节点支持：

- 单次选择多张本地图片。
- 继续追加图片。
- 删除单张图片。
- 清空全部图片。
- 显示原图缩略图、文件名和上传错误。
- 上传图片保存到现有画布资源存储，确保保存、重启、导入导出后仍可用。

连接输入沿用动作裂变的语义：

- 主图片输入：用于批量任务的主图集合。
- 附加图片输入：作为每个任务的共同额外参考图。

对于连接节点输出的多张图片，需要按现有画布图片展开规则展开，并保持稳定顺序。

## 3. 节点数据设计

建议新增 `batchImageGenerator` 节点类型，避免把批量状态强行放入普通 `imageGenerator` 或 `actionFission`。

建议状态结构：

```ts
interface BatchImageGeneratorItem {
  id: string;
  sourceUrl?: string;
  sourceThumbUrl?: string;
  sourceFileName?: string;
  sourceWidth?: number;
  sourceHeight?: number;

  resultUrl?: string;
  resultThumbUrl?: string;
  resultFileName?: string;
  resultWidth?: number;
  resultHeight?: number;

  latestGenerationTaskId?: string;
  status?: "pending" | "queued" | "running" | "completed" | "failed";
  error?: string;
}

interface BatchImageGeneratorState {
  items: BatchImageGeneratorItem[];
  prompt?: string;
  providerId?: string;
  model?: string;
  resolution?: string;
  aspectRatio?: string;
  quality?: string;
  negativePrompt?: string;
}
```

实际字段命名应结合当前 `NativeCanvasNodeData`、schema 规范和持久化约定调整。

## 4. UI 方案

新增独立的 `BatchImageGeneratorNodeBody.tsx`，整体参考 `ActionFissionNodeBody.tsx`。

### 顶部工具栏

- 运行/停止全部任务。
- 只保留网格布局（列表布局已移除）。
- 全部下载。
- 清空输入。
- 删除节点。
- 显示整体进度，例如“生成中 3/10”。

### 单个批量项

每一项展示：

- 输入图片缩略图。
- 文件名或序号。
- “混合图片”标签（存在额外连接图片时显示）。
- 结果缩略图。
- 排队、生成中、完成、失败状态。
- 单张重新生成。
- 单张下载。
- 单张错误信息。

结果预览、放大查看、下载按钮和状态覆盖层尽量复用动作裂变现有实现。

## 5. 任务执行方案

复用现有 Action Fission 的批量任务模式和普通图片生成后端：

- 使用 `startMany` 创建多个独立任务。
- 每个任务的 target 使用新的 item 类型：

```ts
{
  type: "batchImageGeneratorItem",
  nodeId,
  itemId,
}
```

- 支持 API 和 LibTV 两种后端。
- 每个任务的参考图顺序为：
  1. 当前批量项的导入图片。
  2. 主图片连接提供的图片（如产品决定保留该输入）。
  3. 附加图片连接提供的图片。
- 每个任务的图片数量固定为 1。
- 并发数先复用现有 Action Fission 配置，后续再决定是否单独配置。

运行前需要冻结当前图片和提示词输入，避免用户在任务提交过程中修改节点导致任务输入不一致。

## 6. 连接和校验

需要扩展现有画布连接规则：

- 新节点接受图片和提示词连接。
- 支持主图片输入和附加图片输入句柄。
- 阻止自身连接和重复连接。
- 没有本地图片且没有有效图片连接时不可运行。
- 模型不支持参考图时不可运行。
- 超出模型最大参考图数量时不可运行。
- 没有有效提示词时不可运行。
- 连接节点输出多张图片时，保持明确且稳定的参考图顺序。

## 10. 实现前仍需确认的产品决策

以下事项不影响整体架构，但会影响第一版范围：

1. **图片数量上限**：已确认：单次上传最多 50 张。
2. **主图片连接的语义**：已确认：连线接入的图片作为每个任务共同使用的额外参考图，不参与创建批次任务。
3. **连接图片与本地图片的顺序**：当前计划是本地批量图片作为每个任务的第一张，连接图片按连接顺序追加，是否确认？
4. **提示词合并顺序**：建议“节点内提示词 + 外部连接提示词”，是否确认？
5. **批量项删除后的任务**：已确认：删除正在生成的单项时，立即停止对应任务。
6. **重新上传行为**：用户再次选择文件时，建议追加到现有列表，而不是覆盖，是否确认？
7. **结果数量**：第一版是否固定每张输入图生成 1 张结果？建议固定为 1。
8. **批量并发数**：第一版是否继续复用动作裂变并发配置？
9. **输出行为**：节点输出是否需要包含全部成功结果，并跳过失败项？建议是。
10. **命名规则**：结果文件名是否使用“原文件名 + 批量生图”形式，还是沿用普通生图命名规则？

## 11. 已确认的图片连接语义

上传图片决定批次规模和任务数量；通过连线接入的图片作为每个任务共同使用的额外参考图。

例如，批量上传 10 张包含 A 物品的图片，再连接 1 张包含 B 物品的参考图：

```text
任务 1：[上传图片 1, B 参考图]
任务 2：[上传图片 2, B 参考图]
...
任务 10：[上传图片 10, B 参考图]
```

因此：

- 每张上传图片仍然是对应任务的第一张图。
- 连线图片追加到对应任务的参考图列表。
- 连线图片不会额外创建任务，也不会改变批次数量。
- 只要存在连线图片，主图片区域显示“混合图片”标签。
- 第一版不需要单独的“主图片连接”句柄，连线图片统一按额外参考图处理。

当前仍为计划阶段，尚未修改功能代码。

## 已实现：传入目标端口

批量洗图节点左侧在主参考上方新增一个输入端口「传入目标」（handle id `batch-import-target`）：

- **只接受图片**：`edgeDataForConnection` 对这个端口只认图片来源（素材节点、图片生成节点、组），
  文字/提示词来源返回 `undefined`，连接被判定为非法。
- 允许多条边；组或多图节点会展开成多张。
- 检测到该端口有图时，节点标题栏最左侧出现「传入目标」按钮；没有入边（或入边没有图）时按钮不出现。
- 点击一次把**全部**目标图按顺序传成卡片，行为等同于上传图片：
  - 已在卡片里的图（同一个素材地址）默认跳过；
  - 超过卡片上限（50）自动截断，不额外提示；
  - 一次写入 = 一条历史记录，撤销可整体回滚。
- 这些图**不参与参考图**：`collectBatchTargetImages` 与 `collectReferenceInputs` 完全隔离，
  所以生成时发给模型的参考图与以前一致，只有每张卡片的目标图变了。
- 断线或删除上游节点：按钮消失，已经传入的卡片保留（等同于已经上传过）。
- 同一个图片节点可以**分别**连到主参考、附加参考、传入目标三个端口：以前"同一对节点只能有一条连线"的
  重复拒绝规则已取消，现在只拒绝"同一个来源重复连同一个端口"。

动作裂变节点不提供这个端口。
